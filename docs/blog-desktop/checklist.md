# 博客桌面管理器 Checklist

## 实现完整性

- [ ] 选择现有 Hexo 项目后显示站点名称、文章数量和 Git 状态；选择普通目录时显示明确原因（验证：项目检查流程和界面测试）。
- [ ] 选择空目录后可以初始化可运行的 Hexo 项目（验证：使用临时空目录执行初始化并运行 Hexo 检查）。
- [ ] 非空目录不会被初始化流程覆盖（验证：目录中放置保护文件后执行初始化，检查文件内容和初始化结果）。
- [ ] 创建带标题、日期、标签和分类的文章后生成可被 Hexo 识别的 Markdown 文件（验证：创建文章并运行 Hexo generate）。
- [ ] 编辑文章标题和正文后保存，再次打开时正文、已编辑字段和未编辑 Front Matter 字段均正确（验证：文章读写单元测试和手动复开）。
- [ ] 删除文章前要求确认，取消确认不会删除文件（验证：删除流程测试）。
- [ ] Markdown 预览正确显示标题、段落、列表、代码块、链接和图片（验证：Widget 测试和预览页面检查）。
- [ ] 本地 Hexo 预览可以启动、在应用内右侧 WebView 打开、停止，异常退出时显示错误（验证：启动预览、检查侧边栏页面、停止进程和构建失败测试）。
- [ ] 保存文章或点击刷新后，应用内预览显示最新 Hexo 页面（验证：修改标题、保存、刷新侧边栏并检查页面内容）。
- [ ] Git 变更列表显示新增、修改、删除和未跟踪文件（验证：在临时 Git 仓库制造各类变更并检查列表）。
- [ ] 用户取消发布时不会执行 Git push（验证：发布确认流程测试并检查远程仓库提交记录）。
- [ ] 确认发布后按构建、提交、推送顺序执行并显示各阶段状态（验证：使用测试远程仓库执行完整发布）。
- [ ] 发布成功后显示提交信息、站点地址并可打开地址（验证：成功发布后的结果页面检查）。
- [ ] 构建失败、Git 未配置、远程不可访问和冲突时，文章源文件保持不变并给出处理建议（验证：分别构造四种失败场景）。
- [ ] 应用重启后恢复最近项目和非敏感设置（验证：关闭并重启应用后检查恢复结果）。
- [ ] 普通配置文件、界面日志和错误日志不包含 Token、密码或完整凭据（验证：敏感信息扫描）。

## 集成

- [ ] 打开已有项目流程串联项目检查、文章加载、编辑保存和 Git 状态刷新（验证：在现有 `hexo-blog` 项目中完成流程）。
- [ ] 空目录初始化流程串联初始化、项目检查、文章创建和本地预览（验证：使用临时目录完成完整流程）。
- [ ] 保存文章后变更列表立即反映文件修改（验证：编辑保存后刷新 Git 状态）。
- [ ] 发布流程仅使用用户选中的变更，不自动重置其他未提交变更（验证：同时准备选中和未选中文件并检查提交内容）。
- [ ] Hexo 构建输出和 Git 输出会被截断、脱敏并展示在对应阶段（验证：模拟长输出和错误输出）。

## 编译与测试

- [ ] Flutter 静态分析无错误（验证：在 `blog-desktop` 执行 `flutter analyze`）。
- [ ] 单元测试通过（验证：在 `blog-desktop` 执行 `flutter test`）。
- [ ] 桌面 Widget 测试通过（验证：执行相关 Flutter 测试目标）。
- [ ] macOS release 构建成功（验证：执行 `flutter build macos`）。
- [ ] Windows release 构建成功或记录当前环境无法验证的原因（验证：执行 `flutter build windows`）。
- [ ] Linux release 构建成功或记录当前环境无法验证的原因（验证：执行 `flutter build linux`）。

## 安全与异常

- [ ] 应用不会在未经用户确认的情况下执行 Git push（验证：所有发布入口和测试覆盖）。
- [ ] 正在执行构建或推送时显示进行中状态，避免重复启动同一操作（验证：连续触发操作并检查按钮状态）。
- [ ] 进程异常退出、目录被删除、文章格式损坏和端口占用时显示可理解错误（验证：逐项模拟异常）。
- [ ] 发布失败不会删除、回滚或静默修改文章源文件（验证：失败前后比较文件内容和 Git diff）。
- [ ] 检测到 Git 冲突时停止发布，不执行强制推送（验证：构造冲突远程并检查命令记录）。

## 端到端场景

- [ ] 用户在空目录中创建博客：选择空目录 -> 初始化 Hexo -> 创建文章 -> 应用内预览 Markdown -> 启动 Hexo 预览 -> 查看博客页面（验证：使用临时目录完成完整用户流程）。
- [ ] 用户发布已有博客：打开 `hexo-blog` -> 修改现有文章 -> 查看 Git 变更 -> 确认发布 -> 构建 -> 提交 -> 推送 -> 打开 GitHub Pages 地址（验证：使用测试分支或明确的测试远程执行，避免误推送生产分支）。
- [ ] 用户处理发布失败：构造构建失败或 Git 失败 -> 查看失败阶段和建议 -> 修复问题 -> 重新发布成功（验证：完整恢复流程）。
