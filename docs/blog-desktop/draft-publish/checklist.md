# 草稿文章发布转换 Checklist

## 实现完整性

- [x] 新建文章默认是草稿，文章列表显示“草稿”（验证：现有代码和回归测试）。
- [x] 草稿可以保存和预览，保存/预览不改变草稿状态（验证：现有保存/预览流程和回归测试）。
- [x] 没有选中文章点击发布不产生任何发布副作用（验证：发布入口在项目或文章为空时直接返回）。
- [x] 草稿发布显示指定提示，并提供“取消”和“转为正式文章并发布”（验证：发布界面代码和发布决策测试）。
- [x] 取消草稿发布不修改文章、不构建、不提交、不推送（验证：取消决策测试，转换前不调用序列化写回）。
- [x] 确认草稿发布会移除 `draft: true`，其他 Front Matter 和正文不变（验证：单元测试）。
- [x] 非草稿发布不显示草稿转换提示，但仍显示普通发布确认（验证：发布决策测试和流程代码）。
- [x] 绑定博客目录时检测当前分支、`origin` 和 upstream，但不自动推送（验证：`inspectRepository` 只读 Git 状态）。
- [x] 推送成功后刷新列表，当前文章不再显示“草稿”（验证：发布成功路径调用文章列表刷新）。

## 发布流程与失败边界

- [x] 发布顺序为 Hexo generate -> git add -> git commit -> git push（验证：发布编排代码）。
- [x] Hexo 构建失败时草稿状态和原文章内容不变（验证：构建阶段异常恢复快照代码）。
- [x] Git 提交/推送失败时不删除文章、不执行 reset、回滚或 force push，并保留本地文章和本地提交（验证：代码搜索和错误路径检查）。
- [x] 只有推送成功后显示“发布成功”（验证：`PublishOutcome` 测试和发布成功路径）。
- [x] 首次确认发布在待设置 upstream 时使用一次 `git push --set-upstream origin <当前分支>`，成功后后续发布使用普通 `git push`，不再携带 `-u`（验证：单元测试和临时 bare remote 连续推送，最终 upstream 为 `origin/main`）。

## 回归验证

- [x] 现有文章 Front Matter 测试通过（验证：`flutter test`，15 个测试全部通过）。
- [x] 随心记、Markdown 编辑器和应用内预览测试通过（验证：`flutter test`，15 个测试全部通过）。
- [x] Flutter 静态分析无 error（验证：`flutter analyze`，无 error，仅既有提示）。
- [x] macOS 构建成功（验证：`flutter build macos`，生成 Release app）。
- [x] 实现不包含 `git reset`、`git push --force` 或真实 GitHub 测试推送（验证：代码搜索和临时 remote 命令记录）。

## 端到端场景

- [x] 用户创建草稿 -> 保存 -> 预览 -> 点击发布 -> 取消，文章仍是草稿且未产生 Git 发布动作（验证：取消决策测试和发布入口流程）。
- [x] 用户创建草稿 -> 保存 -> 预览 -> 点击发布 -> 转为正式文章并发布 -> 推送成功，列表移除“草稿”且正式页面可构建（验证：转正/序列化测试、成功刷新路径和临时 remote）。
