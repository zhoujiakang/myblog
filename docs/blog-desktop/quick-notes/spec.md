# 随心记 Spec

## 背景

用户需要在写正式博客文章之前，随时记录正在做的事情、临时想法和学习内容。随心记属于当前博客项目，但不能混入 Hexo 的正式文章目录，也不能改变现有博客的目录结构和生成结果。

## 目标

- 在当前博客项目中提供独立的随心记区域。
- 支持快速记录、查看、编辑和删除随心记。
- 支持将一条或多条随心记整理为新的 Hexo 文章。
- 保留原始随心记，整理过程失败时不破坏已有数据。

## 功能需求

- F1: 用户可以在已绑定的博客项目中进入随心记区域。
- F2: 用户可以进入随心记后直接开始所见即所得地编辑内容，不需要直接接触 Markdown 语法、标题表单或标签表单；停止输入后内容自动保存。
- F3: 用户可以按文件更新时间查看随心记列表，并打开记录继续编辑；列表标题优先取正文中的一级标题。
- F4: 用户可以删除随心记，删除前必须确认。
- F5: 随心记以独立 Markdown 文件保存在博客项目根目录的隐藏目录 `.blog-desk/notes/` 中，不进入 `source/_posts`；文件使用 Front Matter 保存标题和其他可选信息。
- F6: 用户可以选择一条或多条随心记开始整理文章；应用将 Markdown 内容合并成文章草稿，只有进入正式文章编辑流程后才填写文章元信息。
- F7: 整理完成后生成新的 Hexo Markdown 文章，原随心记继续保留。
- F8: 随心记目录不存在、记录格式损坏、读写失败或整理文章失败时，应用显示可理解的错误，并保留未受影响的数据。

## 非功能需求

- N1: 创建、编辑和删除随心记不得修改现有 `source/_posts` 文件。
- N2: 随心记目录应被 Hexo 忽略，不参与文章生成和主题渲染。
- N3: 写小记的操作路径应尽可能短，进入页面即可输入，停止输入后自动保存并显示保存状态；文件仍使用 Markdown 保存，但编辑界面不显示 Markdown 源码；文件写入采用可恢复的方式，失败时不留下半截记录。
- N4: 随心记内容不包含敏感凭据，错误提示不泄露系统密钥或完整凭据。
- N5: 用户不需要单独填写标题；应用自动识别正文第一个一级标题，并将其同步到 Front Matter 的 `title` 字段，正文中的一级标题继续保留。

## 不做的事

- 不自动把随心记转换为文章。
- 不自动发布随心记或整理后的文章。
- 不删除或覆盖原随心记。
- 不改变现有 Hexo 主题和文章目录结构。
- 不在本阶段实现全文搜索、云同步、多人协作或 AI 自动改写。

## 验收标准

- AC1: 打开博客项目后可以进入随心记区域，并创建一条记录；重新打开项目后记录仍然存在。
- AC2: 随心记文件位于 `.blog-desk/notes/`，创建和编辑随心记不会新增或修改 `source/_posts` 文件。
- AC3: 用户进入随心记后可以直接编辑格式化内容；界面显示标题、段落、列表和代码块的效果，不显示 Markdown 源码；停止输入后无需点击保存按钮即可自动保存，应用同步 Front Matter 的 `title`。
- AC4: 用户删除随心记前会看到确认提示，取消确认不会删除文件。
- AC5: 用户选择随心记整理文章后，可以编辑文章内容和元信息，并保存为新的 `source/_posts/*.md` 文件。
- AC6: 整理文章后原随心记仍可正常打开，内容没有被覆盖或删除。
- AC7: 模拟随心记损坏、目录不可写或文章保存失败时，应用显示错误，原有随心记和文章文件保持不变。
- AC8: 带有 Front Matter 的随心记可以正常读取、编辑和保存；未修改的字段保持不变，正文一级标题与 `title` 字段保持同步。
