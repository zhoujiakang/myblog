# 随心记 Plan

## 架构概览

随心记沿用现有 Flutter Desktop 工作区和本地项目绑定方式，增加一个独立的工作区页面：

1. 随心记数据层负责目录准备、Markdown 文件读取、原子保存、列表读取和删除。
2. 编辑适配层负责 Markdown 与所见即所得文档模型之间的转换。
3. 随心记应用层负责当前项目路径校验、选中记录、批量整理和错误状态。
4. 随心记表现层提供记录列表、所见即所得编辑器、删除确认和“整理成文章”入口。
5. 文章整理复用现有文章模型和 Markdown 序列化能力，但使用新对象生成文章，不修改原随心记。

## 核心数据结构

### `QuickNote`

- `id`：稳定的唯一标识，用于文件名和列表定位。
- `path`：随心记 Markdown 文件路径。
- `markdown`：文件的完整 Markdown 内容，包含 YAML Front Matter 和正文。
- `displayTitle`：Front Matter 中的 `title` 值；创建或编辑时由正文第一个一级标题自动同步。
- `frontMatter`：YAML 字段集合，至少包含自动同步的 `title`，其他字段由用户自由添加并保留。
- `updatedAt`：文件最后修改时间，用于排序和展示。
- `editorDocument`：编辑器内部的富文本文档状态，不作为项目文件格式保存。

### 随心记文件

- 目录：`<blogRoot>/.blog-desk/notes/`。
- 文件格式：一个随心记一个 `.md` 文件，文件名使用安全的 ID，不使用用户标题作为文件名。
- 文件内容完全由用户编辑；应用自动维护 Front Matter 的 `title` 字段，但保留正文中的一级标题。
- Front Matter 使用现有 YAML 解析和保留未知字段的能力；无法解析时标记该记录损坏并保留原文件。
- 记录时间直接使用文件的修改时间，避免额外表单；Front Matter 保存标题和用户可选的额外信息。

### `NoteToPostDraft`

整理流程使用独立的文章草稿，不直接修改 `QuickNote`：

- `title`：默认使用选中记录的 Front Matter 标题或正文一级标题。
- `body`：按选择顺序合并记录的完整 Markdown 内容，并保留记录之间的分隔。
- `date`：默认使用当前时间。
- `tags`：合并并去重所选记录标签。
- `categories`、`description`、`draft`：使用正式文章编辑器的默认值，允许用户修改。

## 接口

### `QuickNoteRepository`

- `list(String blogRoot) -> Future<List<QuickNote>>`
  - 创建缺失的 `.blog-desk/notes/` 目录。
  - 按文件修改时间倒序返回合法记录。
- `save(String blogRoot, QuickNote note) -> Future<QuickNote>`
  - 解析并保留未修改的 Front Matter 字段。
  - 写入临时文件，成功后替换目标文件，避免留下半截 Markdown 文件。
  - 新记录和更新记录使用同一接口。
- `delete(String blogRoot, String id) -> Future<void>`
  - 只删除对应 ID 文件，不删除目录或其他记录。
- `read(String blogRoot, String id) -> Future<QuickNote>`
  - 供编辑和整理前重新读取最新内容。

### `QuickNoteComposer`

- `compose(List<QuickNote> notes) -> PostDocument`
  - 创建独立的文章对象。
  - 不调用随心记删除或更新接口。
  - 文章保存路径由现有文章创建流程生成，位于 `source/_posts`。

## 模块设计

### 数据层

新增随心记模型和仓库实现。仓库只接受已绑定的博客根目录，并使用路径拼接生成 `.blog-desk/notes`。禁止使用递归清理或覆盖整个 `.blog-desk` 目录。

### 工作区导航

在主窗口导航中增加“随心记”入口。没有绑定博客项目时，该入口不可进入或显示绑定项目提示；绑定项目后进入随心记列表。

### 随心记列表

- 进入页面后提供一个直接可输入的 Markdown 编辑区，减少跳转和表单填写。
- 顶部只保留“新建随心记”“保存”和“整理成文章”等必要操作。
- 列表显示从 Markdown 一级标题解析的标题、正文摘要和更新时间，不显示标签表单。
- 支持选择多条记录；没有选择记录时整理按钮禁用。
- 每条记录提供编辑入口和删除入口。
- 删除前显示确认对话框。

### 随心记编辑器

- 使用所见即所得编辑器直接编辑标题、段落、列表、引用、代码块等内容。
- 提供必要的格式工具栏，不显示 Markdown 源码。
- 保存前将编辑器文档转换回 Markdown；用户输入的第一个标题同步到 Front Matter 的 `title`。
- 新建记录时立即创建草稿文件，避免用户忘记保存时丢失刚输入的内容；退出前仍提供保存状态提示。
- 保存成功后刷新列表并保留当前选择。
- 保存失败时保留表单中的未保存内容。

### 整理文章流程

1. 用户在列表中选择一条或多条随心记。
2. 应用读取最新记录并生成文章草稿。
3. 打开现有文章编辑器，允许修改标题、正文、日期、标签、分类、摘要和草稿状态。
4. 用户确认保存后，使用现有文章保存流程写入 `source/_posts`。
5. 整理成功后返回随心记列表，原记录保持不变。
6. 整理失败时显示错误，不删除或修改任何随心记。

## 模块交互

打开项目 -> 确认博客根目录 -> 准备 `.blog-desk/notes/` -> 读取合法随心记 -> 显示列表。

创建或编辑 -> 更新 Markdown 内容 -> 原子写入 `.md` 文件 -> 重新读取列表 -> 显示成功状态。

选择记录 -> 读取最新内容 -> 生成独立文章草稿 -> 文章编辑器修改 -> 用户确认 -> 写入 `source/_posts`。

任意读取或写入错误 -> 保留当前内存状态和源文件 -> 展示错误 -> 允许重试。

## 文件组织

计划新增或修改以下文件：

```text
blog-desktop/
├── lib/
│   ├── main.dart                         # 导航和工作区集成
│   └── quick_notes.dart                   # 模型、仓库和整理逻辑
└── test/
    └── quick_notes_test.dart              # 数据读写和整理测试
```

实现阶段如果现有单文件结构继续扩大，再将随心记表现层拆到独立文件；本计划不要求无关模块重构。

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 存储位置 | `<blogRoot>/.blog-desk/notes/` | 属于当前项目且避开 Hexo 正式文章目录 |
| 存储格式 | 每条记录一个 Markdown 文件，可带 Front Matter | 与 Hexo 兼容，编辑器和文件格式解耦 |
| 编辑体验 | Flutter Quill 所见即所得编辑器 | 提供桌面端富文本编辑能力，用户不需要接触 Markdown |
| 格式转换 | `markdown_quill` 双向转换 | 保持 Markdown 文件作为稳定持久化格式 |
| 标题同步 | 正文第一个一级标题 -> Front Matter `title` | 用户只写正文标题，Hexo 元信息自动完整 |
| 文件名 | 稳定 ID | 避免标题包含特殊字符导致路径问题 |
| 写入方式 | 临时文件后替换 | 降低应用中断造成半截记录的风险 |
| 整理方式 | 生成独立 `PostDocument` 草稿 | 保留原始随心记并复用现有文章编辑器 |
| 选择模型 | 列表多选 | 支持把多条零散记录合并成一篇文章 |
| Hexo 兼容 | 不写入 `source/_posts` 之外的文章文件 | 不改变现有博客目录和主题生成行为 |
