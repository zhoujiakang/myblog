# 随心记 Checklist

## 实现完整性

- [ ] 已绑定博客项目后可以进入随心记区域（验证：打开现有 Hexo 项目，点击“随心记”导航）。
- [x] 进入随心记后可以直接编辑格式化内容，不需要填写标题或标签表单，也不显示 Markdown 源码（验证：接入 Quill 所见即所得编辑器并通过富文本 Widget 测试）。
- [ ] 正文第一个一级标题会自动同步到 Front Matter 的 `title` 字段，正文标题继续保留（验证：输入 `# 标题`，检查文件内容和列表标题）。
- [x] 没有一级标题的记录也可以保存，并显示默认标题（验证：空 Markdown 编辑器初始化回归测试通过，并在 macOS 界面验证可正常显示）。
- [ ] Front Matter 中的标签、来源和未知字段在编辑保存后保持不变（验证：使用带多个自定义字段的 Markdown 文件编辑并保存）。
- [ ] 停止输入后记录自动保存 Markdown，并显示保存中、已保存或失败状态（验证：输入格式化内容后等待自动保存，检查文件和界面状态）。
- [ ] 随心记按文件更新时间倒序显示（验证：修改两条记录并检查列表顺序）。
- [ ] 删除随心记前要求确认，取消确认不会删除文件（验证：分别确认和取消删除操作）。

## 存储隔离

- [ ] 随心记文件保存在博客根目录 `.blog-desk/notes/`（验证：检查实际文件路径）。
- [ ] 创建、编辑和删除随心记不会修改 `source/_posts`（验证：操作前后比较文章目录和 Git diff）。
- [ ] 随心记不会修改 Hexo 配置、主题文件或生成目录（验证：操作前后检查对应目录时间和内容）。
- [ ] 应用重新打开项目后可以恢复随心记（验证：关闭并重新打开工作区）。

## 整理成文章

- [ ] 可以选择一条随心记整理成正式文章（验证：选择记录并进入文章编辑器）。
- [ ] 可以选择多条随心记，并按选择顺序合并内容（验证：选择两条以上记录，检查生成草稿顺序）。
- [ ] 整理草稿可以编辑正式文章的标题、日期、标签、分类、摘要和草稿状态（验证：在正式文章编辑器修改字段）。
- [ ] 确认保存后生成新的 `source/_posts/*.md` 文件（验证：检查文章文件和 Front Matter）。
- [ ] 整理完成后原随心记仍存在且内容未改变（验证：重新打开原记录并比较内容）。
- [ ] 取消整理或保存失败不会生成或覆盖正式文章文件（验证：取消操作并模拟写入失败）。

## 异常处理

- [ ] 随心记目录不存在时应用可以自动创建（验证：删除 `.blog-desk/notes/` 后重新进入随心记）。
- [ ] Front Matter 损坏时显示可理解错误，其他记录仍可使用（验证：放入损坏 Markdown 和正常 Markdown）。
- [x] 所见即所得内容转换回 Markdown 后，标题、段落、列表、引用和代码块可以重新打开并保持（验证：`round-trips common Markdown blocks through the rich text model` 测试通过）。
- [ ] 随心记目录不可写时显示保存失败，原文件保持不变（验证：模拟无写权限目录）。
- [ ] 整理文章失败时原随心记和正式文章源文件保持不变（验证：模拟文章目录写入失败）。
- [ ] 自动保存与切换记录、删除记录不会互相覆盖（验证：连续快速切换和删除操作）。

## 集成

- [ ] 随心记可以从现有工作区导航进入，并能返回文章页面（验证：在文章、编辑和随心记页面之间切换）。
- [ ] 随心记整理出的文章可以继续使用现有 Markdown 预览、Hexo 预览和发布流程（验证：整理文章后启动预览并检查 Git 变更）。
- [ ] 随心记操作不触发 Git push（验证：创建和整理随心记后检查发布流程未被调用）。

## 编译与测试

- [ ] 新增随心记单元测试通过（验证：运行 `flutter test test/quick_notes_test.dart`）。
- [x] 现有 Widget 测试和文章 Front Matter 测试通过（验证：运行 `flutter test`，6 个测试通过）。
- [x] 静态分析无新增错误（验证：运行 `flutter analyze`，无 error，仅保留原有 info 提示）。
- [x] macOS Release 构建成功（验证：运行 `flutter build macos`）。
- [ ] Windows 和 Linux 构建在对应环境验证，当前环境不支持时记录原因（验证：运行对应平台构建命令）。

## 端到端场景

- [ ] 用户快速记录并整理文章：打开博客项目 -> 进入随心记 -> 直接输入 Markdown -> 自动保存 -> 选择记录 -> 编辑正式文章信息 -> 保存到 `source/_posts` -> 原随心记仍可查看。
- [ ] 用户处理带元信息的记录：打开带 Front Matter 的 Markdown -> 修改正文一级标题 -> 自动保存 -> 检查 `title` 同步且其他字段保留。
- [ ] 用户处理失败场景：制造随心记或文章写入失败 -> 查看错误 -> 修复权限 -> 重试成功，原始内容未丢失。
