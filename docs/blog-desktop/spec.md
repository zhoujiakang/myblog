# 博客桌面管理器 Spec

## 背景

当前博客基于 Hexo 构建，文章以 Markdown 文件保存在博客项目目录中，并通过 GitHub Pages 对外发布。现有流程需要在编辑器、终端和浏览器之间切换，创建文章、查看效果和发布过程彼此分离。

本项目要提供一个桌面应用，让博客作者在一个界面中绑定本地 Hexo 项目，管理文章，预览生成结果，并将变更发布到 GitHub。第一阶段只支持本地项目目录，远程仓库直连留作后续扩展。

## 目标

- 让用户选择并绑定一个本地 Hexo 博客项目目录。
- 让用户查看、创建、编辑和删除博客文章。
- 让用户在编辑 Markdown 的同时查看接近真实博客的渲染预览。
- 让用户启动本地博客预览，并在应用中打开或查看预览结果。
- 让用户检查变更并将博客构建、提交和推送到 GitHub Pages。
- 在配置错误、构建失败或发布失败时提供可理解的错误信息，并保留用户文章内容。

## 功能需求

- F1: 用户可以选择一个本地目录作为博客项目，并确认该目录是可识别的 Hexo 项目。
- F2: 用户可以选择一个空目录，由应用在其中初始化一个可运行的 Hexo 项目；初始化完成后该目录可以直接进入文章管理、预览和发布流程。
- F3: 用户可以查看已绑定项目的基本信息，包括项目路径、站点名称、文章数量和当前 Git 分支或提交状态。
- F4: 用户可以浏览文章列表，并按标题、更新时间或发布状态查看文章。
- F5: 用户可以创建文章，并编辑标题、正文、日期、标签、分类、摘要和草稿状态等 Hexo 文章信息。
- F6: 用户可以打开已有文章进行编辑，并保存为符合现有 Hexo 格式的 Markdown 文件，不破坏未编辑的 Front Matter 字段。
- F7: 用户可以删除文章；应用必须在删除前要求确认，并在删除失败时说明原因。
- F8: 用户可以在编辑过程中查看 Markdown 渲染结果，代码块、图片、链接和常用文章元信息应能够正常显示。
- F9: 用户可以启动本地博客预览；应用应在主窗口右侧打开一个独立的原生预览窗口，并显示真实 Hexo 页面、启动状态、访问地址和停止预览的操作。
- F10: 用户可以在文章编辑窗口旁同时查看独立预览窗口；保存文章或手动刷新后，预览窗口应重新加载当前博客内容，并在主窗口移动时保持在其右侧。
- F11: 用户可以查看本地项目的待发布变更，包括新增、修改和删除的文件，并确认后开始发布。
- F12: 用户可以发起发布流程；应用依次完成博客生成、Git 提交和推送，并显示每一步的状态与输出摘要。
- F13: 发布成功后，应用显示成功信息、最新提交信息以及配置的博客访问地址，并提供打开网页的操作。
- F14: 应用应保留用户未保存的编辑内容；任何构建、Git 或发布失败都不能静默覆盖文章内容。
- F15: 用户可以配置或修改 GitHub Pages 发布所需的仓库、分支、提交信息和站点地址等项目设置。
- F16: 应用重新启动后可以恢复最近一次绑定的项目路径和非敏感界面设置；敏感凭据不以明文保存。

## 非功能需求

- N1: 应用第一阶段支持 macOS、Windows 和 Linux 桌面运行，核心文章和发布流程保持一致。
- N2: 应用必须兼容现有 Hexo 文章格式和当前主题的常见渲染内容，不要求用户迁移文章。
- N3: 文件写入、构建和发布操作应在界面中明确显示进行中状态，避免用户误以为操作已完成。
- N4: 发布操作不得在没有用户确认的情况下执行 Git 推送。
- N5: GitHub 凭据由本机 Git 凭据管理能力提供或由系统安全存储管理，应用不在普通配置文件中保存明文 Token 或密码。
- N6: 文章列表和编辑界面在常见规模的个人博客中应保持可用，不因加载全部文章而明显卡顿。
- N7: 应用发生异常时必须给出可操作的错误信息，并保留足以定位问题的日志。

## 不做的事

- 第一阶段不直接通过 GitHub API 编辑远程仓库。
- 第一阶段不支持多个博客项目同时打开。
- 第一阶段不提供多人协作、账户系统或云端同步。
- 第一阶段不重构现有 Hexo 主题，不改变博客页面设计；应用内预览使用现有 Hexo 主题生成的页面。
- 第一阶段不实现图片素材管理、媒体上传或图床配置。
- 第一阶段不自动解决 Git 冲突；检测到冲突时暂停发布并要求用户处理。
- 第一阶段不支持在应用内配置完整的 GitHub OAuth 服务。
- 初始化 Hexo 时不自动覆盖非空目录中的现有文件；非空目录仍按已有项目目录处理或提示用户选择其他目录。

## 验收标准

- AC1: 选择现有 Hexo 项目目录后，应用能识别项目并显示站点名称与文章数量；选择非 Hexo 目录时显示明确原因。
- AC2: 选择空目录并确认初始化后，应用能创建可运行的 Hexo 项目；初始化失败时显示原因，且不覆盖用户已有文件。
- AC3: 用户能创建一篇带标题、日期、标签和分类的文章，保存后在项目的文章目录中生成可被 Hexo 识别的 Markdown 文件。
- AC4: 用户能打开现有文章、修改标题和正文、保存，再次打开时内容和未编辑的文章元信息保持正确。
- AC5: 用户能在编辑界面看到 Markdown 渲染预览，至少验证标题、段落、列表、代码块、链接和图片。
- AC6: 用户启动本地预览后，应用内侧边栏能显示包含目标文章的真实 Hexo 页面，并能刷新和停止预览。
- AC7: 用户保存文章后，侧边栏刷新能显示最新文章内容；预览服务失败时显示具体错误而不是无限加载。
- AC8: 存在本地变更时，应用能列出变更文件；用户取消发布时不会执行推送。
- AC9: 用户确认发布后，应用能执行构建、提交和推送；成功时显示成功状态和访问地址，失败时显示失败步骤与可读错误。
- AC10: 发布过程中发生构建失败、Git 未配置、远程不可访问或冲突时，文章源文件保持不变，应用显示对应处理建议。
- AC11: 应用重启后能恢复最近绑定的项目；敏感凭据不会出现在普通配置文件或界面日志中。
- AC12: 在 macOS、Windows 和 Linux 中完成一次初始化或绑定、创建、编辑、应用内预览和发布流程，核心行为一致。
