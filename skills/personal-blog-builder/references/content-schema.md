# 内容层：机制与栏目约定

全站文案与数据都住在 `content/` 的 Markdown 里。**改文案只动 .md，不改代码。**

这份文档分两部分：前半是**机制**（解析规则，必须遵守，违反了就不生效）；后半是**栏目约定**（栏目由用户选，这里给常见类型的字段参考）。

---

## 一、解析机制（必须遵守）

内容层的实现方式决定了下面这些约束，换个写法就读不出来：

1. frontmatter 夹在首尾两行 `---` 之间，正文写在闭合 `---` 之后（渲染为 `body`）。
2. 每行 `key: value`，按**第一个**冒号切分，所以 value 里可以含冒号（URL、时间都安全）。
3. value 两端成对的引号会被自动剥掉。不确定要不要引号时，不加。
4. **不支持嵌套 YAML、不支持数组、不支持多行值。**
5. 列表字段用 ` | ` 分隔（两侧带空格）。
6. 列表顺序 = **文件名排序**，用数字前缀控制：`01-xxx.md`、`02-xxx.md`。
7. **slug = 文件名去掉 `.md`**，直接变成 URL：`content/articles/hello.md` → `/#/articles/hello`。改文件名 = 改链接，已经分享出去的会失效。
8. 空目录合法：返回 `[]`，页面自动显示配置好的空状态。空目录靠 `.gitkeep` 保留。
9. slug 建议用英文小写短横线。中文文件名可以，但 URL 会被转义成一串 `%E4%BD%A0`，分享出去很难看。

---

## 二、栏目：由用户决定，不预设

**不要默认给用户开"作品 / 技能 / 文章"三栏。** 栏目是承诺：开了就要有内容，长期空着比不开更尴尬。栏目应该从访谈里"你手上有什么"反推。

按数据形态，栏目分四种。选型决定了要不要做详情页、要不要做筛选：

| 类型 | 结构 | 适合放什么 | 成本 |
| --- | --- | --- | --- |
| 集合型 | 列表页 + 详情页 | 作品、文章、笔记、书单、照片集 | 高（两套页面） |
| 条目型 | 只有列表，无详情 | 技能、工具清单、外链收藏 | 低（一套页面） |
| 单体页 | 一个长页面 | 关于、联系、Now、简历 | 最低 |
| 归档型 | 按时间/标签分组的列表 | 文章归档、日志 | 中（要分组逻辑） |

**取舍建议**：存货少于 3 条时，不要做集合型（列表只有一项很空）。存货多的，才值得为它做详情页。用户想开很多栏目的，先问"哪个是主角"，只给主角做详情页，其余做条目型。

---

## 三、常见栏目的字段约定

下面三类是最常见的组合，可以直接用；用户要的栏目不在这三类里，按下节自定义。

### 作品 / 项目（集合型）

```markdown
---
title: 项目名
desc: 一句话说清它解决什么问题。
tags: 开源 / 工具
role: 独立开发
year: "2025"
stack: Vue 3 / Vite / Node
link: https://github.com/you/repo
---
正文（详情页 body）：背景、做了什么取舍、结果如何。
```

- 列表卡只消费 `title` / `desc` / `tags`。
- 详情页额外消费 `role` / `year` / `stack` / `link`，**这四项留空就整项不渲染**，不要留冒号或空标签。
- `year` 建议加引号，避免被当成数字。

### 技能 / 条目（条目型，无详情页）

```markdown
---
title: 前端工程
content: Vue 3 / Vite / 设计系统落地
---
```

- `content` 通常用等宽字体、强调色渲染，读起来像"键值对"，正好符合技能的观感。
- 条目型不需要详情页，点击行为要么去掉，要么给外链。

### 文章（集合型 + 归档）

```markdown
---
title: 文章标题
date: 2025.03.14
tag: 工程实践
excerpt: 一句话摘要，显示在详情页导语位置。
---
正文。
```

- `date` 决定归档年份与排序，兼容 `2025.03.14` / `2025-03-14` / `2025/03/14` / `2025`；缺失显示 `—` 并排最后。
- `tag` **单值**，不是数组。筛选 chips 由所有文章的 tag 去重自动生成。
- `excerpt` 只在详情页用，列表不显示。
- 正文当前渲染器**不解析 Markdown 语法**，`**粗体**` 会原样显示。写纯文本 + 空行分段。要支持粗体/代码块，得自己接一个轻量渲染器。

## 四、自定义栏目

用户要一个不在上面三类里的栏目（"在读"、"收藏"、"时间线"、"友链"），按三步定：

**① 先定它属于哪种类型**（见上表）。这决定要几个页面。

**② 再定字段**，只保留真正要显示的：

| 数据形态 | 建议字段 |
| --- | --- |
| 有标题 + 描述 | `title` `desc` |
| 有封面图 | 加 `cover`（放 `src/assets/`，用相对路径） |
| 有时间 | 加 `date`（统一格式，方便排序和分组） |
| 有分类 | 加 `tag`（单值）或 `tags`（` / ` 分隔） |
| 有外链 | 加 `link` |
| 纯文本条目 | 只留 `title`，正文写内容 |

**③ 字段定完再动手写视图。** 顺序反了会改两遍：先写页面再想字段，最后一定会为了迁就代码删掉本来该有的信息。

字段名一旦定了，**视图、内容、文档三处必须一致**。字段名写错不会报错，只是页面上安静地不出现——这类问题最难排查。

## 五、`content/site.md` — 全站配置

所有能读到的字都在这里，组件里不写句子（原因见 `design-spec.md` 第六节）。

| 字段 | 用途 |
| --- | --- |
| `name` / `tagline` | 首页大字标题，两行 |
| `identity` | 身份行，` | ` 分隔 |
| `github` / `email` / `phone` / `qq` | 联系方式，点击复制，不生成 mailto/tel |
| `copyright` | 页脚版权 |
| `siteUrl` | 站点绝对地址，OG 图绝对 URL 依赖它，**上线必须是真实域名，带二级域** |
| `nav` | `标签::路由`，` | ` 分隔 |
| `seoTitle` / `seoDescription` | 注入 `<title>` / `description` / OG / Twitter Card |
| `{page}Label` / `{page}Title` / `{page}Intro` | 各栏目头部 |
| `empty{Page}Label/Title/Text` | 各栏目空状态，**写成给访客的话** |
| `tagEmptyText` | 筛选无结果提示，`{tag}` 是占位符 |
| `viewAll` / `viewMore` / `ctaText` / `copyBtn` / `copyTip` | 通用文案，`copyTip` 里的 `{email}` 会替换 |

新增栏目时，**同步补**这一栏的 `{page}Label/Title/Intro` 和 `empty{Page}*`，并把 `nav` 加一项。漏了会出现"页面能进，但标题是空的"。

## 六、`about.md` 与 `home.md`

### about.md

| 字段 | 用途 |
| --- | --- |
| `codingSince` | 起始时间，兼容 `2023.09` / `2023-09` / `2023/09/01` / `2023` |
| `nowTitle` | Now 区标题 |
| `now` | 列表，` | ` 分隔 |
| body | 关于页 bio 正文 |

**统计数字一律算出来，不写死。** 默认三张卡的口径是：项目数 = 集合型栏目条数、文章数 = 文章数、年限 = `yearsSince(codingSince)` 算到今天（保留一位小数，运行时算）。

栏目变了，统计口径也要跟着改：

- 用户没开文章 → 不要放"分享文章"卡，换成别的（如"在读"条数），或者只留两张。
- 用户开了五个栏目 → 不要五个都上，**选三个**最能代表他的。统计卡是"第一印象"，不是目录。
- 用户不想公开年限 → 去掉，换成"咖啡杯数"这类无害数字，或者只留两张卡。

**绝对不要为了让页面好看而编数字。** 访问者看出数字是假的，整页的可信度都会掉。

### home.md

```markdown
---
exploreLabel: // 栏目
exploreTitle: 逛逛这些
scrollHint: 往下滑
---
```

`content/home/NN-*.md` 每个文件是一张入口卡：

```markdown
---
title: 作品 / Works
desc: 精选项目、实验与小工具。
to: /works
---
```

入口卡数量 = 栏目数量。**只有一栏时不要用卡片墙**，直接单栏流（见 `design-fragments.md` 布局骨架），一张卡孤零零放在那里很空。

## 七、加一条内容的正确姿势

1. 在对应目录新建 `NN-slug.md`（数字前缀控顺序，slug 决定 URL）。
2. 只填该栏目需要的字段，不需要的行直接删掉，不要留空值。
3. 正文用普通 Markdown 段落，空行分段（不解析行内语法，见上文）。
4. `npm run dev` 热更新即可看到，不用重启。

**不要替用户编内容。** 素材不够就留空并说清楚，空状态本身是设计的一部分，比假数据体面。
