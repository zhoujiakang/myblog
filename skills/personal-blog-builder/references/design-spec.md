# 设计规范（可参考，不是教条）

这份文档给的是**一套经过验证的默认值**：网格、字阶、组件行为、动效、空状态、文案位置。

**怎么用**：用户没有明确偏好时，直接用这里的值，能保证出来不难看；用户有明确偏好（"我要大标题特别大""我要紧凑一点"）时，按用户的来，但要理解偏离了什么——下面每条都写了"为什么是这个值"，就是为了让你能判断改了会不会出问题。

具体的配色、圆角、阴影配方见 `design-fragments.md`；风格怎么定见 `styles.md`。

---

## 一、网格与留白

| 项 | 默认 | 为什么 |
| --- | --- | --- |
| 容器宽 | `max-width: 1280px`，居中 | 再宽正文行长会超过可读上限（约 75 字符） |
| 左右边距 | `24px` | 移动端够用，桌面不显局促 |
| 子页顶部 | `padding-top: 100px`（移动 `64px`） | 首屏不贴顶，留出"呼吸"；贴顶会显得像没做完 |

**间距节奏**：组件内 `4/8/12/16/18/24`，区块间 `30/34/38/48/60`。不确定就取最近的档——随手写 `37px` 不会报错，但整页会失去统一感，且没人说得清哪里怪。

正文行长建议控制在 **60–72 字符**。宽屏下正文区域要给 `max-width`（如 `720px`），否则一行排到 1200px 根本没法读。

## 二、字阶

| 层级 | 规格 | 用途 | 备注 |
| --- | --- | --- | --- |
| 页面主标题 | 48px / 900 / 行高 1.2（移动 34px） | 各页头部 | 900 是气场的来源，降到 700 会软 |
| 分区标题 | 22–28px / 700 | 卡片标题、年份 | |
| 条目标题 | 17px / 700 | 时间线、列表条目 | |
| 导语 | 16px / 400 | 页头 intro、详情 lead | 用 `--muted`，不用 `--ink` |
| 正文 | 16px / 行高 1.8–1.9 | bio、详情 body | 中文行高低于 1.7 会挤 |
| 等宽小标 | 12–15px | 标签、日期、单位、按钮 | 全站统一，是识别度的锚点 |
| 主导航 | 16px | 未激活 `--muted`，激活 `--ink` | 不要用颜色区分激活态，用明度 |

**四个字重角色不要混**：900 只给页面大标题，700 给标题，400 给正文，等宽自成一路。混合使用（比如卡片标题也用 900）会让页面失去层次。

## 三、组件的默认行为

### 卡片

底 + 圆角 + 淡描边 + 轻阴影，四件套。**描边不能省**——深色主题里阴影几乎无效，去掉描边卡片就消失了。

悬停：`translateY(-2px)` + 阴影加深 + 描边变强，180ms 左右。位移超过 3px 会像"跳"而不是"浮"。

### 按钮

高 44–52，左右内边距 20–24，等宽字体 15px。悬停上浮 1px + 透明度 0.9，不做颜色反转（反转会让按钮闪烁感很强）。

### 小标签

等宽字体，`//` 开头（`// 作品集`）。这是全站标点习惯，新写的文案要延续；突然出现一个 `【作品集】` 会很突兀。

### chips（筛选）

`padding: 7px 15px`，胶囊圆角。激活态填强调色 + 反白文字。**必须检查激活态文字对比度**——强调色往往偏亮，白字会糊。

### 时间线

左侧 2px 竖线 + 9px 圆点。圆点中心用**页面底色挖空**（`var(--bg)`），不是白色——用白色在深色主题里会变成一撮白点。竖线用 `--border-strong`，用 `--border-soft` 几乎看不见。

### 详情页外壳

顺序固定：`kicker`（等宽小字，如 `2025.03.14 · 工程实践`）→ `title` → `lead` → `meta` 行（角色 / 年份 / 技术栈 / 链接）→ `body` → `cta`。

`meta` 行里**任何一项为空就整项不渲染**，不要留冒号或空标签。

### 导航

激活项 ≥ 10px 差异或明度差，且要有非颜色线索（字重或下划线）——只靠颜色区分，色弱用户看不出来。

## 四、动效

全站只用一种入场动效：滚动揭示，`opacity 0 → 1` + `translateY(22px) → 0`，0.7s，`cubic-bezier(.22,1,.36,1)`。

- 列表错峰 `i * 80ms`，超过 8 项不再累加（否则最后一项要等一秒多）。
- 只动 `opacity` 和 `transform`。动 `top/left/width` 会触发重排。
- 悬停反馈 150–180ms，位移 ≤ 6px。
- **`prefers-reduced-motion: reduce` 必须兜底**：关动画 + 强制 `opacity: 1`。初始态是透明的，不兜底就是这个用户打开看到空白页。

不要加第二种入场动效（缩放、模糊、旋转）。一种显得克制，两种以上显得廉价。

## 五、空状态

空状态是**给访客看的**，不是给自己的待办提醒。

三行结构：

```
// works                     ← 等宽小标，说明这里是什么
更多作品，敬请期待             ← 一句标题，不解释原因
我正在打磨一些新项目，稍后再来逛逛。  ← 一句安抚
```

规则：

- **绝不**出现 `content/` 路径、"去添加 md"、"暂无数据"这类内部语言。
- 不要道歉过度（"非常抱歉这里还什么都没有"会让访客替你觉得尴尬）。
- 空栏目要能正常访问、正常显示空状态——404 或白屏是最差的结果。

判断标准：把一个陌生人放到这个页面，他应该觉得"这里将来会有东西"，而不是"这里坏了"。

## 六、文案必须放在 content/

这是整套方案里最值得坚持的一条：**页面上所有能读到的字，都放在 `content/` 的 Markdown 里，组件里不写中文句子。**

包括：导航标签、页头标题与导语、按钮文案、空状态三行、页脚、404 文案、SEO 标题与描述、复制成功提示。

### 为什么

- 用户改文案不用碰代码，也不怕改坏结构。
- 同一个组件能复用到多个页面（标题从配置来，不是写死的）。
- 文案集中之后，语气才统一——散落在 20 个组件里的句子，很难保持同一个声音。
- 换语言、换站名、换标点习惯，改一处就够。

### 怎么做

```markdown
<!-- content/site.md -->
nav: 首页::/ | 作品::/works | 关于::/about
emptyWorksLabel: // works
emptyWorksTitle: 更多作品，敬请期待
emptyWorksText: 我正在打磨一些新项目，稍后再来逛逛。
```

```js
// 视图里读配置，不写字符串
<h1>{{ site.worksTitle }}</h1>
<p>{{ site.emptyWorksText }}</p>
```

### 自检

```bash
# 组件里不该有成句的中文（注释除外）
grep -rnP "[\x{4e00}-\x{9fa5}]{4,}" src --include=*.vue | grep -v "^\s*//"
```

出现结果就搬去 `content/`。

**例外**：`aria-label` 这类无障碍文本、开发者注释可以留在组件里。它们不是给人看的页面文案。

---

## 七、整体自检

- [ ] 文案全部来自 `content/`，组件里没有成句中文
- [ ] 空状态在对访客说话
- [ ] 字阶没有超过 5 档
- [ ] 间距都在节奏表里
- [ ] 640px 宽无横向滚动
- [ ] `prefers-reduced-motion` 下内容可见
- [ ] 任一详情页的 `meta` 行为空时不留残渣
- [ ] 404 页能正常显示（访问一个不存在的路由）
- [ ] 对比度：正文 ≥ 7:1，辅助文字 ≥ 4.5:1，小标签 ≥ 3:1
