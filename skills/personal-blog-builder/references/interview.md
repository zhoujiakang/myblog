# 访谈：把"我想做个个人网站"变成能施工的方案

用户开口时，信息量通常接近于零。他的原话可能是"帮我做个个人博客""想有个自己的主页""做个作品集"——这三句话背后可能是完全不同的东西：一个想持续写技术文，一个想在面试时甩个链接，一个想把散落的作品收拢。

**不要在信息不足时开工。** 做出来再改，比问清楚再做贵得多：改栏目要动路由和内容层，改风格要动一整层令牌，改定位往往意味着重做首页。

这篇文档给的是**问的顺序和问法**。目标不是把所有字段填满，而是让你在开工前能用一句话说出"这个站首页长什么样、有什么栏目、什么调性"。

---

## 一、开工前先判断：要不要采访

**要采访**：用户只给了意图（"做个博客"），或只给了身份（"我是做后端的"）。

**不用采访**：用户已经给了明确清单——"五个栏目：首页、项目、文章、关于、友链；深色；用 Vue"。这时只确认缺的一项，直接进方案。

**只问一句就够**：用户说"照你上次给我做的那样再做一份"。这时问的是差异，不是全量。

---

## 二、问的顺序：从"处境"问到"细节"

一共三轮，每轮 3–4 个问题，一屏问完。**不要问成问卷**——问卷是让人填字段，采访是让人说事。

### 每条问题都带例子，让用户接着说

开放问题负责给他自由，例子负责让他有话可说。两个必须一起用——**光问"你想有哪些栏目"，多数人答不上来**，因为那是让他做专业决策。

对照一下：

| 只会开放 | 带例子 |
| --- | --- |
| "你想要哪些栏目？" | "你有哪些想记录的呢？比如文章、作品、照片，或者别的什么？" |
| "你想要什么风格？" | "你更接近哪种：像纸质笔记本、像终端，还是像产品官网？" |
| "你手上有什么素材？" | "写过的文章、做过的项目、拍的照片——哪些是真有存货的？" |

右边那列多出来的只有半句话，但它把"从零想"变成了"从我给的里认"，难度差一个量级。

三条纪律：

- **结尾那句"或者别的什么"不能省。** 省了，用户就只在你给的例子里挑——你以为在采访，其实在做选择题。他答出例子里没有的东西，才是这轮最值钱的信息。
- **一次 3–4 个，且跨类型。** 全举"作品、项目、案例"这种同类词，用户会被框在那一类；只举一个，他会以为你只会做那一种。文字 / 作品 / 图像 / 清单 / 时间流，各举一个。
- **例子是引子，不是承诺。** 你说"比如照片"，用户可能会说"对，我想放照片"——这不等于你已经答应了做图库栏目。后面该怎么取舍，仍然按他的存货量和主次来定。

### 第 1 轮：定位（最容易被跳过、也最不该跳过）

这一轮决定后面所有事。三个问题：

**① "这个站主要给谁看？"**

不要接受"所有人"。追问一句"最想让哪一类人打开它"，选项给他：面试官 / 潜在客户 / 同行 / 朋友和家人 / 就是自己存个档。

答案决定首页第一屏放什么：
- 面试官 → 第一屏就要能看出你会什么、做过什么，作品前置，文章往后放
- 潜在客户 → 第一屏要有"我能帮你解决什么问题"，配案例
- 同行 → 可以放观点、技术细节、在读什么
- 朋友 / 存档 → 自由度高，可以放生活侧面

**② "对方关掉页面时，你希望他脑子里剩下一句话是什么？"**

这句就是 tagline 的来源，也是整个站的语气基准。

用户答不上来（很常见）→ 换成三选一：
> "你想让人记住的是——'这人做的东西挺有意思'、'这人靠谱能干活'、还是'这人在认真想事情'？"

三选一远好过开放题。他选了之后，你再把它写成一句话给他确认。

**③ "你手上现在有什么？"**

这是全场最重要的一问，因为它**反推栏目**（见下一轮）。具体问：

> "写过的文章、做过的项目、在学的东西、拍的照片、看过的书、做过的设计、跑过的比赛——哪些是真的有存货的？大概几条？"

一定要问数量。**有 3 篇存货和"以后会写"是两回事**：前者可以开文章栏目，后者开了就是长期空页面。

用户答"没什么东西"时，他多半是把"存货"理解成了"成品"。换个说法再举一遍：

> "不用是完成品。记到一半的笔记、做废的项目、随手拍的照片都算——你电脑里现在有什么是能拿出来给人看的？"

### 第 2 轮：结构 + 调性

**① 栏目：先问"想让人看到什么"，带例子；再收敛成组合**

第一轮问的是**手上已经有什么**，这一轮问的是**想让人看到什么**——这两件事经常不一样：有人只有作品存货，但真正想让人看见的是自己在学什么。

带例子问，然后停住让他说：

> "除了刚才那些，这个站你还想放点什么？比如在做的项目、读过的书、拍的照片、写过的笔记、想去的清单，或者一条按时间排的记录——有吗？"

他说的东西按"该怎么装"归类，这一步你来做，不要让他选：

| 他说的 | 装成什么 | 成本 |
| --- | --- | --- |
| 有一批同类东西（3 条以上） | 集合型：列表 + 详情页 | 中 |
| 想持续更新、按时间排 | 时间流：归档时间线或日志 | 低 |
| 只有一个页面的事（关于我 / 现在 / 联系） | 单体页，不用列表 | 最低 |
| 只是罗列（书单、链接、装备） | 清单页，条目点外链 | 最低 |

把他说的东西归好类，再按第一轮的存货量反推成 2–3 个组合（每个一句话说清长什么样），让用户挑或改：

| 组合 | 长什么样 | 适合 |
| --- | --- | --- |
| 作品前置型 | 首页大字 + 插画 + 3–4 张入口卡（作品/文章/关于）；作品是主角 | 设计、前端、独立开发者 |
| 纯写作型 | 首页直接是文章列表 + 简短自我介绍；没有卡片墙 | 长期写字、技术博客 |
| 简历型 | 单页纵向：简介 → 经历 → 技能 → 联系方式；不需要详情页 | 求职、咨询、自由职业 |
| 素材库型 | 按分类归档（照片/书/收藏），详情页放大图 | 摄影、读书、收藏 |
| 混合型 | 首页入口卡 + 文章 + 一个自定义栏目 | 什么都有一点 |

**他说了七八样，说明还没定主次**——别照着建八个栏目。问一句"你自己最想让别人先看哪一个"，那就是主栏目，其余降级或先不开。

**不要直接给五栏全上。** 栏目是承诺：开了"作品"就要有作品，空着不如不开。用户选不出来的，就问"你更希望别人先看你的作品，还是先看你写的东西"——二选一能定下主次。

**② 调性：先问参照物，再给几个具体的风格例子**

"你想要什么风格"这个问题，用户答"简洁大气"等于没答。分两步问。

先问参照物：

> "有没有哪个网站、App 或者产品，你打开觉得'这样挺舒服'？说个名字就行。"

拿到参照物后，翻译成具体的三件事讲给用户听：底色（亮/暗/中间调）、密度（松/紧）、强调方式（几乎无色 / 一个小高亮点缀 / 大面积色块）。让他确认。

他有参照物，到此就够，不用再念例子。**他没有（很常见）时别退回开放题**——念几个具体的风格画面让他认：

> "那我给你几个感觉，你看哪个顺眼：
> ① 纸质笔记本——米白底，字大、留白多，几乎不用颜色；
> ② 终端——黑底、等宽字、一个荧光色做高亮，像在终端里看东西；
> ③ 产品官网——冷白底、细边框、一个蓝色点缀，信息排得很整齐；
> ④ 杂志——白底黑字、大号衬线标题、一条彩色细线分隔；
> ⑤ 手账——微黄底、圆角很大、轻噪点，像贴了贴纸的页面；
> ⑥ 数据看板——灰底、密集的小卡片、数字特别大。"

三条用法：

- **一次念 4 个以内，按他的身份挑。** 给后端念"终端 / 杂志 / 数据看板"；给摄影念"杂志 / 手账 / 产品官网"。全念 6 个他反而挑不出来。
- **例子要在不同维度上拉开**——明暗、冷暖、密度、字体各来一个。四个都是"干净的浅色站"，等于只给了一个选项。
- **这些例子是你现场想出来的引子，项目里可能一个都没有，也不必和 reference 里的设计一致。** reference 里那套是给你动手时参照的，不是给用户挑的菜单。例子的唯一任务，是让用户从"说不出"变成"这个不像、那个有点像"。他挑中之后不要照着原样实现，翻译成明暗 / 密度 / 强调三件事再确认一遍（落地方法见 `styles.md`）。

**③ 报库存：把"现成就能用"和"能按这个方向做"分开说**

不要默默替他决定，也不要让例子冒充库存。三件事都要讲：

1. **现成有一套什么**——现查 `src/styles/themes/`，用气质和适合场景讲，别凭记忆报（清单见 `styles.md` 第二节）。
2. **你刚挑的那个方向也能做**——如果它不在现有主题里，明说要新做一套、要花点时间调，别含糊过去。
3. **现在不定也不影响开工**——之后改一行就能换。

> "项目里现在现成有一套：暖白纸感，字大留白多，几乎不用颜色，只有一个金色做点缀。可以直接用。
> 你刚才说的杂志感没有现成的，但能按那个方向做一套，就是要多花点时间调字和分隔线。
> 这两条路都行，现在不决定也不耽误后面，风格之后换只改一行。"

**例子说成"我们有"，用户选了才发现要现场做，是最常见的失望来源。**

用户说"都不喜欢"→ 别问"那你想要什么"，直接做 2–3 个候选让他看（做法见 `styles.md`「用户不满意时」）。**人对自己不想要什么很清楚，对想要什么很模糊**——给具体东西让他否，比让他描述有效得多。

### 第 3 轮：落地细节（能跳就跳）

- **联系方式**：哪些愿意公开？GitHub / 邮箱基本要有；手机、微信、QQ 问一句"要不要放、要不要脱敏"。
- **素材**：有没有头像、插画、项目截图？没有就说清楚会用占位图，不是最终效果。
- **上线**：有没有域名？有没有 GitHub 账号？没有也不影响建站，先把 `siteUrl` 写成占位并标注。

这一轮不要问：技术栈、要不要 TypeScript、用不用 Tailwind、部署到哪个平台。这些是你要决定的，不是用户该操心的。

## 三、用户说"你看着办"怎么办

这是最常见、也最容易做错的分支。**不要把"看着办"理解成"随便做"**——它的真实意思是"我没有判断力，你给我一个具体的、我能看懂的东西"。

正确的做法是给**默认提案**：一段具体的画面描述 + 一句理由，让他改。

> "那我按这个来：首页一行大字你的名字加一句话，右边一张插画；往下是四张入口卡（作品、文章、关于、联系）；再往下是最近三篇文章和一句招呼。整体走暖白纸感，字大、留白多、几乎不用颜色，只有一个金色做点缀。
> 理由：你提到主要是给面试官看，所以作品放最前；你手上有 3 个项目，够撑起一个栏目，文章先不开，等你写了几篇再加。
> 哪里不对你直接说，我改。"

这段话干了四件事：给出可想象的具体画面、说明取舍依据、主动暴露"我没做什么"、留了修改口子。**比问十个问题更能推进。**

示例里的"暖白纸感"是按项目现有主题写的——**实际要换成你现查到的那套的气质**，别照抄。用户在此之前挑过某个风格例子时，提案就按那个方向说。

## 四、什么时候可以停止采访

判断标准只有一条：

> **你能用一句话说出"首页第一屏长什么样、有哪几个栏目、什么调性"，并且用户点头了。**

满足就可以开工。不要为了"问全"而继续问——问过头会让用户觉得在被审，也容易在他还没想清楚的地方逼出错误的决定。

缺的东西可以留白并在交付时标注。**留白比编造安全**：栏目空着有体面的空状态，"以后再加"是常态。

## 五、采访产出：一份 brief

采访完，在对话里用这张表回给用户确认（不必写文件，除非用户要）。表里的每一项后面都要能落到具体实现上。

| 项 | 内容 | 落到哪 |
| --- | --- | --- |
| 定位 | 给谁看 + 一句话目的 | 决定首页信息优先级 |
| 一句话 | 关掉页面后剩下的那句话 | `content/site.md` 的 `tagline` |
| 身份行 | 三个关键词 | `site.md` 的 `identity` |
| 栏目 | 从例子里认出来的 + 已经有的存货；标明主栏目和先不开的 | 路由 + `content/` 目录 + 导航 |
| 调性 | 亮/暗、松/紧、强调方式（参照物或他挑中的例子翻出来的） | 主题令牌 |
| 风格选择 | 用现成哪套 / 按哪个例子新做 / 暂不定 | `styles/themes/*.css`；新做时把明暗、密度、强调三条写进文件头注释 |
| 素材 | 有存货的数量、有没有图 | `content/<栏目>/` + `assets/` |
| 联系方式 | 公开哪些 | `site.md` |
| 上线 | 域名 / 仓库 | `public/CNAME` + `siteUrl` |

## 六、几条容易犯的错

- **把"以后会写"当成"现在有文章"**：开了栏目就是承诺，长期空着比不开更尴尬。
- **替用户编内容**：编出来的项目和数字，用户第一次打开就会要求删掉，还伤信任。宁可空。
- **只问不给例子**：光问"你想放什么""你想要什么风格"，用户卡住，最后回一句"你定吧"——他放弃了，你也没拿到信息。例子是这轮问话的一半。
- **例子开出的口子收不回来**：说了"比如照片"，用户顺着列了七八样，别照着全建。问他哪个是主角，其余降级。
- **把例子说成已有**：随口举的风格被当成承诺，交付时才发现没有，比一开始就说"这个要新做"更伤信任。
- **在采访阶段聊技术**：用户不关心，且会让他误以为要自己做技术决策。
- **只问不答**：采访是对话，不是表单。他说"不知道"，你要给判断，而不是把问题再抛回去。
- **问了两轮还在问**：说明你在逃避做判断。剩下的用默认提案兜住。
