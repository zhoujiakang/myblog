# 改一个已经建好的站

用户在成品站上提改动时读这份。先判断改动落在哪一层，再动手——走错层是最常见的返工原因。

| 用户要改的 | 改哪里 | 注意 |
| --- | --- | --- |
| 一句话、标题、联系方式 | `content/site.md` | md 能解决的不要改代码 |
| 一篇文章 / 一个作品 / 一条条目 | `content/…/NN-slug.md` | 改文件名 = 改 URL，等于废掉已分享的链接 |
| "统计数字不对" | 不改数字 | 数字是算出来的：改对应栏目目录，或改 `codingSince` |
| 配色 / 圆角 / 阴影 / 字体族 | `src/styles/themes/*.css` | 只改令牌，不动组件 |
| "这里排版有问题" | 先判断是间距、对齐还是字阶 | 按 `design-spec.md` 的规格修，别手调数字 |
| 布局 / 栏目 / 动效 | 组件 + `architecture.md` | 先读结构，再改 |

## 只改内容

- 加一条：在对应栏目目录建 `NN-slug.md`，frontmatter 见 `content-schema.md`。常见组合是文章（`title/date/tag/excerpt`）和作品（`title/desc/tags/role/year/stack/link`）；如果用户开的栏目不在这两类里，按他自己定的字段填，别套模板。
- 改文案：`content/site.md` 里对应的键；组件里不该出现中文句子，出现了说明这是历史遗留，顺手挪进配置。
- 删内容：删文件即可，列表和统计会自动跟着变。

改完不需要重启 dev；如果页面没变，先怀疑 frontmatter 字段名写错（不会报错，只是不显示）。

## 换一套风格

用户只说"想换个感觉"时，不要直接生成一套塞过去。先问他有没有参照物；说不上来就念几个具体的风格画面让他认（话术见 `interview.md` 第 2 轮第 ② 问，一次 4 个以内，在明暗 / 冷暖 / 密度上拉开）。还拿不准，再做 2–3 款候选——**真做出来让他点着看**，比文字描述准得多。做法见 `styles.md` 的「用户说不好看」一节。

两处必查：深色主题的卡片要留描边（阴影在深底上几乎看不见）；示例插画若是暖米底，配深色主题像贴错的纸，得换图或去掉首页大图。

## 改结构

加栏目、改路由、动 `content.js` 时按 `architecture.md` 走，别在组件里临时拼数据。

## 改完做什么

1. `npm run build`，确认零报错。
2. `npm run dev` 看改动那一页，顺带看一眼手机宽度有没有横向滚动。
3. 改的是视觉 → 按 `styles.md` 的换风格自检过一遍；改的是内容 → 确认空状态和统计数字跟着对了。

## 不要做

- 用户没要求时，不要顺手重构。他说改个颜色，回来发现十个文件变了，下次就不敢让你动了。
- 不要为了改一句话去动 `.vue`。
- 不要把统计数字写死回组件里。
